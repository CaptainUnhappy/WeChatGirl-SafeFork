# 视频压缩与识别

在「能力目录」安装视频插件，再打开左侧「视频识别」。同一页可以启停插件，授权单个好友和群聊，或允许所有当前和以后添加的聊天。保存后，授权私聊和群聊中的原生视频会触发识别，群聊无需艾特。页面底部可选择本地视频进行压缩或测试。完整操作步骤见[插件说明](../../optional-extensions/video-workbench/README.md)。

微信视频需要先下载到 Windows 微信的本地缓存。程序直接在本机定位并抽帧，没有固定的聊天文件大小或时长上限，只把抽样拼图交给识图模型。若程序提示文件未找到，在 Windows 微信打开视频并等下载完成，再发一次。识别范围为抽样画面。手动工作台仍支持 32 MiB、3 分钟以内的文件。微信缓存目录和消息标识参考 [WeFlow](https://github.com/hicccc77/WeFlow/blob/main/electron/services/videoService.ts)。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| 压缩分辨率上限 | 720 | 按原比例缩小，可选 480、720、1080 |
| 压缩强度（CRF） | 26 | 范围 20–34，数值越高，输出通常越小 |
| 画面识别分段数量 | 6 | 可填写 2–16 的整数。按时间均匀分段，每段取一帧，按播放顺序排列 |
| 视频识别模型 | 跟随聊天与图片分流 | 从 DSH 目录选择独立识图模型。手动选择只影响视频，保持原聊天和图片模型设置 |

工作台显示输出体积。较短或已经压得很小的视频转码后可能变大。识别需要 DSH 与可用的识图模型，压缩只依赖本机 FFmpeg。首次升级宿主后，从托盘完整重开 DSH。

FFmpeg 单独提取完整音轨，本机 SenseVoice 将整段音频一次转写。调整画面分段数量不会影响声音。单次整段转写支持 5 分钟以内，超过时仍分析画面并标明音轨未转写。群聊回复结合画面与对白，工作台分别显示两项结果。无音轨、未安装模型或转写失败时，画面识别仍可用。原始音频在本机处理。

在 Windows 微信开启文件自动下载后，程序会在后台等待当前视频的缓存，最长约五分钟。等待下载、压缩抽样画面和识别时，同一个群仍可继续正常聊天。识别后由该聊天当前的人格卡结合画面与对白回复原会话，并核对微信服务器回执。提交结果不明确时，只补查回执，避免重复发送。服务器回执表示消息已提交到微信服务器。处理中的任务会随聊天服务关闭而停止，重开后可重新发视频触发识别。

缓存缺失时，程序会尝试用已登录的 Windows 微信打开原视频触发下载。此操作可能切换前台聊天。下载操作按顺序执行，轮到时再次核对原消息。优先用相邻消息和排列顺序定位，显示时长只用于补充匹配。新消息把视频挤出可见区域后，会在原会话内向上查找。无法确认目标时会继续等待缓存，超时后提示手动打开原视频。

点击视频后继续检查微信缓存。若过一段时间缓存仍未出现，且视频气泡仍显示「下载」，程序会重试。日志中的 `VIDEO_DOWNLOAD_CLICKED` 表示已点击，`VIDEO_CACHE_READY` 表示读取器已找到可供处理的缓存文件。

文件定位会优先查询消息记录的文件标识，再按资源表和微信自己的 `hardlink.db` 索引匹配缓存。这样文件名与消息里的 MD5 不同时，也能找到微信保存的原文件。索引结构参考 [WeFlow 的 Windows 媒体读取实现](https://github.com/334456777/WeFlow/blob/main/crates/weflow-native/src/media.rs)，画面与对白分开解析参考 [AstrBot 视频上下文插件](https://github.com/ZAKOsiesta/astrbot_plugin_video_context)。聊天视频由 Windows 微信负责下载。
